FortiManager — Policy Blocks

Policy Blocks are reusable policy containers inside an ADOM. A policy copied into a block becomes independent from its source, so later edits to the source do not propagate. Central NAT, NGFW mode and offload level are block-level design choices. When reused policy behaves unexpectedly, verify the block mode, copied rule content, target package and install preview rather than assuming source-package inheritance.

Primary documentation

FortiAnalyzer — Log forwarding and aggregation

Default forwarding sends selected logs while retaining a local copy. Aggregation differs: the receiving FortiAnalyzer must explicitly accept aggregation and the client defines aggregation mode, server identity, credentials and schedule. Transport interruption can buffer logs, so troubleshoot generation, local storage, queue state, transport, receiver authorization and indexing as separate boundaries.

Primary documentation

FortiSwitch — Storm control

Storm control measures broadcast, unknown-unicast and multicast packet rates and drops excess traffic above the configured threshold. It is not a spanning-tree replacement. Per-switch local override and burst-size behavior can make nominally similar switches behave differently. Validate traffic class, counters, threshold, burst setting and inheritance before simply raising a limit.

Primary documentation

FortiNAC — Endpoint compliance

Endpoint compliance evaluates connecting hosts against security requirements. Agent choice changes the evidence model: Dissolvable Agent is temporary, Persistent Agent remains installed, Mobile Agent targets mobile devices, and Passive Agent scans without installation. Troubleshooting should identify the expected agent, execution state, observed posture, policy match and resulting enforcement.

Primary documentation

FortiNAC-F — Network access policy ordering

A network access policy joins a user/host profile with a network access configuration. Matching is top-down and first-match wins; hosts can be re-evaluated as user, host or location facts change. A broad catch-all placed too high shadows lower policies. Evidence should include host/profile facts, connection location, ranking, selected configuration and actual enforcement result.

Primary documentation

FortiPAM — Password changers

Password changers automate secret rotation and can verify secret health. Changer and verifier functions are distinct, and reconciliation support depends on changer type. Decompose a failure into target reachability, changer selection, privilege, generated-password constraints, change execution, verification and vault update instead of treating rotation as one opaque transaction.

Primary documentation

FortiAP — CAPWAP liveness on high-latency links

Recent Fortinet scenario material shows how CAPWAP Echo Request/Response liveness and max-retransmit determine when a FortiEdge Cloud-managed AP tears down its DTLS session and rejoins. High latency and NAT-state behavior can therefore masquerade as wireless instability. Capture echo timing, missed responses, DTLS state and NAT lifetime before changing RF parameters.

Scenario source

FortiAuthenticator — Trusted-domain authentication boundary

A recent child-domain case demonstrates that LDAP object reachability is not equivalent to successful Windows-domain authentication. Domain join/trust state and trusted-domain handling can determine whether a child-domain RADIUS authentication succeeds. Troubleshoot DNS/domain discovery, machine join/trust, LDAP lookup, RADIUS method, Windows authentication result and FortiAuthenticator policy as separate boundaries.
