Exclusion inventory

1. FortiGate — SCTP multihoming across virtual clusters

An SCTP INIT can traverse VDOM1 while a backup heartbeat traverses VDOM2. Since VDOM session state is separate, the second path can drop heartbeats despite IP reachability. The documented sctp-session-without-init setting permits session creation without observing INIT; validate support for the current policy mode and verify the remote peer receives heartbeats.

2. FortiManager — Retrieve versus policy-package authority

Retrieve imports FortiGate running configuration into the device database, not the ADOM policy package. A package-owned value can overwrite a locally retrieved change on the next installation. Compare running state, device revision, package objects and install preview before deciding whether to import policy or preserve device-specific configuration.

Primary Fortinet feature documentation

3. FortiAnalyzer — JSON API request/response audit

FortiAnalyzer local Event Log can record JSON API requests, responses, or both using the jsonapi-log setting. Correlate API user, operation, Session ID and response with the downstream task result. An accepted API call does not prove target enforcement, and local event retention may remove older audit evidence.

Primary Fortinet feature documentation

4. FortiSwitch — Routed VLAN interfaces

An RVI binds a physical port or trunk to a routed interface using internal VLAN 4095 and optional VRF. It follows the bound port state and supports routing protocols, but excludes 802.1X, MAB, DHCP snooping and other access-port features. Verify with diagnose ip router fwd l3-rvi-info and check routing adjacency separately.

Primary Fortinet feature documentation

5. FortiAP/Wireless — EST/SCEP wired certificate bootstrap

FortiAP 7.6.4+ can use WTP-profile EST/SCEP settings to obtain CA and client certificates for wired 802.1X. First verify enrollment trust and URL reachability; then check cw_diag -c cert and wireless auto-certificate events. A downloaded certificate does not prove RADIUS authorization or production VLAN assignment.

Primary Fortinet feature documentation

6. FortiNAC — Register as Device placement

Device in Host View retains host aging, port MAC visibility and NAC policy eligibility. Device in Network Inventory behaves as infrastructure, does not expire, and is not subject to ordinary Network Access Policies. The Manage In choice can therefore alter enforcement without changing a switch configuration.

Primary Fortinet feature documentation

7. FortiNAC-F — Trap-driven L2/L3 host learning

Link-up traps can trigger delayed MAC-table polling and retries. L2 polling provides MAC and port; L3 ARP polling adds IP association. Check trap receipt, switch forwarding table, polling timestamps, and L3 device group membership. MAC-notification traps can reduce redundant polling where supported.

Primary Fortinet feature documentation

8. FortiAuthenticator — Dynamic RADIUS reply attributes

RADIUS user and group attributes can be static or dynamically derived from user fields. Supported dynamic types differ: remote LDAP groups allow String or IP, while remote SAML and MAC groups lack the Dynamic option. Compare Access-Accept AVPs with NAS authorization; authentication success does not prove correct VLAN or privilege.

Primary Fortinet feature documentation

9. FortiPAM — Native launcher tunnel encryption

Native launcher traffic traverses a FortiClient-to-FortiPAM HTTP/TLS/TCP tunnel and then a separate target connection. The guide requires Tunnel Encryption when HTTPS interception lies in the path; it is strongly recommended for cleartext protocols such as VNC. Portal login does not prove the native launcher transport works.

Primary Fortinet feature documentation

10. FortiSIEM — Watch Lists as dynamic incident memory

One correlation rule can insert a typed incident attribute into a tenant-scoped watch list; a later rule can test membership with IN. Attribute type mismatches prevent insertion. Verify the original incident, list entry, consumer rule and expiry separately to avoid stale suspicion or missed correlation.

Primary Fortinet feature documentation

11. FortiSASE — Branch On-ramp IKEv2 mode config and BGP

FortiGate operates as an IKEv2 dialup client to a FortiSASE PoP. Mode config assigns the tunnel interface address used for BGP peering; overlay network IDs distinguish tunnels over multiple underlays. Verify IKE, mode config, BGP routes and actual cloud policy separately.

Primary Fortinet feature documentation

12. Secure SD-WAN — Packet duplication and de-duplication

A duplication rule sends verbatim packet copies across eligible SD-WAN zone members; the hub can forward the first arrival and discard later duplicates. Force and on-demand have different trigger semantics. Check source and destination captures, SLA conditions, rule match and added bandwidth before enabling broadly.
