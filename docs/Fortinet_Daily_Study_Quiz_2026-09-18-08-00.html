1. FortiGate — Deep inspection certificate resigning

During SSL deep inspection, FortiGate resigns the server certificate. A CA certificate used for resigning must contain Subject Key Identifier for Authority Key Identifier to be included in the modified certificate. Fortinet documents fixes for missing AKID behavior across supported FortiOS branches.

Primary: FortiGate Administration Guide
Scenario: AKID deep-inspection scenario

2. FortiManager — Device-identification template dependency

FortiManager can manage interface settings through templates, but a documented FortiManager 7.4.x issue can skip device-identification when the interface role is Undefined or WAN. Installation preview and actual FortiGate state are separate evidence boundaries.

Primary: FortiManager Administration Guide
Scenario: device-identification install issue

3. FortiAnalyzer — HA synchronization and report execution

FortiAnalyzer HA provides primary failover, secure log/data synchronization, and report processing on secondary units. Current documentation supports up to four units, requires the same FortiAnalyzer series and operation mode, and applies the smallest managed-device license when cluster members have different licenses.

Primary: FortiAnalyzer HA
Scenario: FortiPortal reporting with FAZ HA

4. FortiSwitch — FortiLink discovery across L2 extension

Standalone FortiSwitch units can emit discovery traffic across an extended Layer-2 domain. A reachable remote FortiGate switch controller can respond and adoption can alter managed configuration. The operational boundary is discovery reachability rather than geographic site.

Primary: FortiSwitch documentation
Scenario: unintended FortiLink adoption

5. FortiAP/Wireless — Cloud firmware download transport

A FortiEdge Cloud-managed FortiAP firmware workflow depends on outbound HTTPS reachability used to retrieve firmware. Fortinet documents TCP/8443 as required for the affected download path; event evidence includes fw-download-failed and HTTPS code 4.

Primary: FortiAP documentation
Scenario: firmware download failure

6. FortiNAC — FortiLink visibility/control boundary

FortiNAC REST APIs can retrieve and update host state and enforce access. In FortiLink-managed FortiSwitch environments, successful credential validation alone does not prove endpoint visibility or VLAN-control capability; the FortiGate/FortiSwitch integration path must also be operational.

Primary: FortiNAC REST API
Scenario: FortiLink visibility/control

7. FortiNAC-F — Token REST authentication for FortiLink

FortiNAC-F FortiLink requirements changed with newer FortiOS. FortiOS 7.4.8+ and 7.6.4 require token-based REST API authentication; session-based username/password API login is no longer supported at the documented 7.6.4 boundary.

Primary: FortiNAC-F FortiLink requirements
Scenario: visibility/control scenario

8. FortiAuthenticator — SCIM identity lifecycle

FortiAuthenticator documents SCIM as REST/JSON-based identity synchronization with client/server roles. Identity creates, updates, and deletes can be synchronized, and reading identities can help detect directory inconsistencies. This is provisioning lifecycle, distinct from runtime RADIUS authentication.

Primary: FortiAuthenticator SCIM
Scenario: child-domain authentication boundary

9. FortiPAM — HTTP secret autofill Web Proxy dependency

For HTTP secrets using autofill, FortiPAM can proxy the browser-to-target workflow. Fortinet documents a failure where redirect to port 5001 authentication produces Failed to load resource when Web Proxy is disabled; target Web Proxy and Explicit Web Proxy on the FortiPAM interface are required in that scenario.

Primary: FortiPAM documentation
Scenario: HTTP autofill failure

10. FortiSIEM — CMDB as analytics context

FortiSIEM's CMDB/discovery model supplies asset and relationship context used by analytics. Event ingestion and contextual modeling are separate boundaries: an event can arrive while service/entity relationships remain incomplete. Validate discovery and CMDB relationships before blaming correlation logic.

Primary: FortiSIEM documentation
Scenario: FortiSIEM Community

11. FortiSASE — Endpoint groups versus user groups

FortiSASE endpoint groups organize endpoints and can drive endpoint-profile assignment; AD-backed group viewing requires an AD connection. Fortinet notes constraints such as parent-domain import affecting subdomain import. Endpoint groups are not interchangeable with user groups used in access and policy contexts.

Primary: FortiSASE endpoint groups
Scenario: user groups vs endpoint groups

12. Secure SD-WAN — ADVPN 2.0 edge discovery and path management

ADVPN 2.0 moves shortcut intelligence toward spokes: shortcuts use underlays available on both spokes and are selected according to matching link-health criteria. Fortinet states this reduces dependence on earlier specific BGP designs such as route reflection and recursive next-hop mechanisms. The documented feature is IPv4-only.

Primary: ADVPN 2.0 edge discovery/path management
Scenario: FortiGate Community
